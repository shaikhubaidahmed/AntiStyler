# COCO API Validation
- **Conversion Methodology**: The YOLO `test/labels/` and `test/images/` were programmatically converted to a temporary COCO JSON using `scripts/evaluate_coco_gtsdb.py`. YOLO normalized coordinates were denormalized and clipped to image boundaries. YOLO class IDs were mapped 1:1 to COCO category IDs. YOLOv7's `best_predictions.json` (which uses string IDs) was remapped to integer image IDs to satisfy PyCOCOTools requirements.
- **COCO JSON Location**: `evaluation_data/gtsdb_coco/instances_gtsdb_test.json`
- **Pycocotools Version**: 2.0.11
- **Evaluation Parameters**: IoU type = `bbox`, IoU threshold = `0.50`
- **Internal YOLOv7 Result**: mAP@0.50 = 0.314
- **COCO API Result**: mAP@0.50 = 0.316
- **Difference**: 0.002
- **Explanation**: A 0.2% difference is expected and normal. It arises from YOLOv7's internal Python/PyTorch evaluation (which approximates COCO's 101-point interpolation) versus the official PyCOCOTools C-based evaluator. The results are scientifically consistent.

# Limitations
- The mAP@0.50 score (0.316) reflects the inherent difficulty of small object detection in GTSDB without heavily tuning the hyperparameters or utilizing anchor re-calculation. However, as a baseline, it establishes a functional lower bound for comparative analysis. 
- Some classes had very few instances in the test set (e.g. `ANIMALS`, `DANGER`), leading to mAP values of 0.0 for those specific classes due to detection failures or extreme sparsity.
